# 検証計画と拡張設計

このドキュメントは、Plamo Design Feedback AI を企業の開発改善ツールとして発展させる場合に、何を検証し、どのように拡張するかを整理したものです。

本プロジェクトは学習・ポートフォリオ用のプロトタイプです。実在商品、公式データ、実際のレビュー、金型データは使用していません。以下の検証例も、考え方を示すための架空例です。

## 現状の位置づけ

現在のアプリは、レビュー文と架空の部品特徴を入力し、ルールベースで分類、リスクスコア算出、改善案生成を行います。

実務上の品質判定モデルではなく、次の仮説を検証するMVPです。

- ユーザーの不満を、設計・金型・説明書・ユーザー体験の改善観点へ変換できるか
- ランナー状態と完成後状態を分けることで、検査観点を整理できるか
- 部品特徴を加えることで、自由記述だけでは見えにくいリスク要因を説明できるか
- 改善案だけでなく、検証方法まで一緒に提示できるか

## スコア妥当性の検証例

実務に近づける場合は、現在のルール重みを試作レビューや測定値で校正します。

| 検証対象 | 現在の推定 | 比較する実測・観察データ | 判定例 |
| --- | --- | --- | --- |
| アンテナ部品 | 小型部品かつ切り出し時破損リスクが高い | 切り出し時破損率、ゲート跡視認性、初心者コメント | ゲート位置変更後に破損コメントが減ればルール妥当 |
| 肩関節 | 可動部かつ固さ・白化リスクが高い | 可動初期抵抗、白化発生率、組立時の不安コメント | クリアランス調整後に抵抗値と不安コメントが下がれば妥当 |
| 腰接続 | 保持力不足とポージング不安定が高い | 装備あり/なしの自立時間、ポーズ保持率 | 保持形状変更後に保持率が上がれば妥当 |
| 説明書工程 | 誤組み・左右間違いのリスクがある | 初心者の誤組み回数、組立時間、質問件数 | 拡大図追加後に誤組みが減れば妥当 |

このように、スコアは「正解値」ではなく、試作評価で優先確認すべき箇所を並べるための仮説として扱います。

## Before/After検証の考え方

改善案を出して終わりにせず、改善前後で比較する指標を置きます。

| 観点 | Before | After | 見る指標 |
| --- | --- | --- | --- |
| 設計 | 軸径・受け側クリアランス未調整 | 面取り/R追加、クリアランス調整 | 可動初期抵抗、白化発生率 |
| 金型 | 外観面に近いゲート位置 | 裏側・側面・影になる位置へ移動 | ゲート跡視認性、処理時間 |
| 説明書 | 工程図のみ | 拡大図、左右比較、注意アイコン追加 | 誤組み回数、組立時間 |
| UX | 不安コメントを個別確認 | カテゴリ別に集計し改善優先度化 | 不満コメント率、満足コメント率 |

## LLMを組み込む場合の拡張設計

外部LLMを使う場合も、既存の関数入出力を維持します。

```text
feedback_text
  -> analyze_feedback(feedback_text)
      -> issue_categories
      -> detected_parts
      -> severity
      -> cause_candidates
      -> improvement_suggestions
  -> calculate_risk_score(classification, part_features)
  -> generate_actionable_fix_plan(record)
```

LLM化する場合の方針:

- `analyze_feedback()` の戻り値スキーマは変えない
- LLMの出力はJSONとして受け取り、許可カテゴリ以外は破棄する
- `risk_score` はLLMの主観値にせず、説明可能なスコアリング層で計算する
- LLM失敗時は現行のルールベース分類へフォールバックする
- 機密情報や実在商品のレビューを扱う場合は、社内ルールに従って匿名化・アクセス制御を行う

## CAD・試作データと連携する場合

将来的に実務データと連携する場合は、以下のような項目が必要です。

| データ | 使い道 |
| --- | --- |
| 部品ID、部品名、ランナー番号 | フィードバックと対象部品の紐づけ |
| ゲート座標、ゲート種類、配置面 | ゲート跡・切り出しリスクの分析 |
| 肉厚、リブ、R形状、軸径、受け径 | 破損・白化・保持力の推定 |
| 材料、想定荷重、可動回数 | 可動部や荷重部位のリスク補正 |
| 試作レビュー、不具合報告 | スコア重みの校正 |
| 組立時間、誤組み回数 | 説明書・工程改善の検証 |

## 面接での説明ポイント

このプロトタイプは、AIの精度を誇張するものではありません。

狙いは、自由記述レビューを開発改善に使える形へ構造化し、設計・金型・説明書・UXの各担当が確認しやすい情報へ変換することです。

現在はローカルで動くルールベースMVPとして作り、あとからLLM、CAD、試作レビュー、品質データへ拡張できるように責務分離しています。
